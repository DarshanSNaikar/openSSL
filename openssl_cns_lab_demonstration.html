CRYPTOGRAPHIC HASH FUNCTION (INTEGRITY)

SHA-256 Hashing & The Avalanche Effect

SHA-256 maps arbitrary data to a strict 256-bit (64 hex character) digest. It is mathematically strictly one-way (pre-image resistant) and cannot be decrypted.

💡 Cryptographic Principle: The Avalanche Effect dictates that flipping just one single character causes >50% of the output bits to change drastically in an unpredictable manner.

✓ One-Way Mathematical Guarantee:
A cryptographic hash cannot be reversed or decrypted. Unlike encryption, no key exists that recovers the input from the digest.
ASYMMETRIC CRYPTOGRAPHY

RSA-2048 Key Generation, Encryption & Decryption

Generate a real RSA-2048 key pair using the browser's Web Crypto API, then use the Public Key to encrypt and the Private Key to decrypt a message — exactly how OpenSSL works.

STEP 1 — KEY GENERATION

Generate RSA-2048 Key Pair (Web Crypto API)

Equivalent to: openssl genrsa -out private.pem 2048

🔒 Private Key (private.pem)
SECRET • NEVER SHARE

Contains prime factors (p, q), modulus (n), and private exponent (d). Used for Decryption and signing. Guard with chmod 600.

-----BEGIN RSA PRIVATE KEY----- MIIEowIBAAKCAQEAz9v0L8mZ1N5H8k0r...[2048-bit Modulus n] e=65537 (0x10001)... d=[Secret Private Exponent]... p=[Prime Factor 1 (1024-bit)]... q=[Prime Factor 2 (1024-bit)]... -----END RSA PRIVATE KEY-----
🌐 Public Key (public.pem)
SHAREABLE • DISTRIBUTABLE

Contains only modulus (n) and exponent (e=65537). Used for Encryption and signature verification. Safe to distribute publicly.

-----BEGIN PUBLIC KEY----- MIIBIjANBgkqhkiG9w0BAQEFAAOCAQ8AMIIBCgKCAQEAz9v0L8mZ1N5H8k0r... [2048-bit Modulus n derived mathematically from Private Key] IDAQAB (e = 65537) -----END PUBLIC KEY-----
✅  Real RSA-2048 key pair generated via Web Crypto API — Ready for Encryption & Decryption
STEP 2 — RSA ENCRYPTION (PUBLIC KEY)

🔐 Encrypt with Public Key

Only the holder of the matching Private Key can decrypt this. Algorithm: RSA-OAEP with SHA-256.
openssl rsautl -encrypt -inkey public.pem -pubin -in msg.txt -out enc.bin

STEP 3 — RSA DECRYPTION (PRIVATE KEY)

🔓 Decrypt with Private Key

The Private Key (held only by the receiver) decrypts the RSA ciphertext using modular exponentiation.
openssl rsautl -decrypt -inkey private.pem -in enc.bin -out decrypted.txt

⚠️ Important: RSA is too slow for large data. In practice, OpenSSL uses RSA to encrypt an AES session key, then uses AES to encrypt the actual data. This is called Hybrid Encryption (used in TLS, PGP, HTTPS).
AUTHENTICITY & NON-REPUDIATION

Digital Signature & Integrity Verification

The sender signs the document hash using their Private Key. The receiver independently computes the hash and verifies the signature using the sender's Public Key.

STAGE 1: DOCUMENT & HASH

"Authorize transfer of $5,000 to Bob"

STAGE 2: PRIVATE KEY SIGN
Encrypt Hash with Alice's Private Key
SIG: a9f81b37c...256-byte-signature
Only Alice holds the private key, establishing Non-Repudiation.
STAGE 3: PUBLIC KEY VERIFY
Bob Decrypts & Compares Hash
If (Decrypted_Hash == Computed_Hash) ➔ Verified OK.

INDUSTRY DEPLOYMENT

Real-World OpenSSL Applications

How OpenSSL powers global cybersecurity infrastructure across protocols, operating systems, and internet standards.

🌐
HTTPS Website Security
Powers the TLS handshake for web servers (Apache, Nginx) protecting sensitive web traffic on TCP port 443 against interception.
🛡️
Secure Host Communication
Provides underlying cryptographic primitives for OpenSSH, SFTP file transfer, and OpenVPN / WireGuard tunneling.
📜
SSL/TLS Certificates & PKI
Generates Certificate Signing Requests (CSRs) and verifies the X.509 chain of trust between Root CAs, Intermediates, and servers.
💾
Data Encryption (Rest & Transit)
Secures database storage, full disk encryption tools, and cloud storage buckets (AWS S3, Google Cloud Storage).
✍️
Digital Signatures & Code Signing
Ensures that software binaries, operating system updates, and Git commits have not been tampered with by malware.
🔑
Secure Key Generation
Provides cryptographically secure pseudorandom number generators (CSPRNG) for Diffie-Hellman and Elliptic Curve Key Exchange.

Cryptographic Mapping to the CIA Triad

The three foundational pillars of information security mapped directly to OpenSSL's core engines.

AES-256-CBC / GCM
CONFIDENTIALITY

Ensures data cannot be read or understood by unauthorized adversaries without possession of the secret key.

SHA-256 / SHA-384
INTEGRITY

Guarantees that any unauthorized tampering, modification, or bit alteration in transit is immediately detectable.

RSA / ECDSA SIGNATURES
AUTHENTICITY

Confirms the true identity of the author and establishes non-repudiation (the author cannot deny having sent it).
